## Token limits (state in the note's `scope:` frontmatter)

The owner contributes to **public** repos of others and asks about their own. `GITHUB_TOKEN_READ` is a
fine-grained PAT scoped to **one resource owner** (their account): it reads their repos and **public repos of
other owners**. **Private org repos are out of scope** (needs a second org-approved token; not planned); search
silently omits them (missing results, no error). Token expires 2026-11-19: a 401 must fail the job loudly.

## 1. `src/core/sources/involvement.ts`

```ts
export type Bucket = "assignedIssues" | "myOpenPrs" | "reviewRequests" | "mentions";
export interface InvolvementItem { repo: string; number: number; title: string; url: string; updatedAt: string; state: string }
export interface InvolvementSnapshot {
  login: string;
  assignedIssues: InvolvementItem[]; myOpenPrs: InvolvementItem[];
  reviewRequests: InvolvementItem[]; mentions: InvolvementItem[];
  recentRepos: { fullName: string; lastActivityAt: string; reason: string }[];
  totals: Record<Bucket, number>;   // real counts before capping
  fetchedAt: string;                // kv only, never rendered
  partial: string[];                // failed buckets, sorted
}
export interface InvolvementOpts {
  token: string; login?: string; maxPerBucket: number;
  exclude?: string[];               // vault repo (its own commits would loop)
  previous?: InvolvementSnapshot | null; now: string; fetch: Fetcher;
}
export const INVOLVEMENT_KV = "gh:involvement", LOGIN_KV = "gh:login";
export const MAX_FETCHES = 8;       // counting fetch wrapper; the 9th call throws
export function fetchInvolvement(o: InvolvementOpts): Promise<InvolvementSnapshot>;
export function parseSnapshot(raw: string | null): InvolvementSnapshot | null;  // null on bad shape
export function readInvolvementSnapshot(store: Pick<Store, "kvGet">): Promise<InvolvementSnapshot | null>;
```

**Primary: ONE `POST https://api.github.com/graphql`** with the query in PLAN §F.3 verbatim
(aliases `viewer.repositoriesContributedTo`, `assigned`, `myPRs`, `reviews`, `mentions`,
`rateLimit`). Headers/timeout as in `sources/github.ts`. Use variables, never interpolation:

| var | value |
|---|---|
| `$assigned` | `assignee:<login> is:issue is:open archived:false` |
| `$mine` | `author:<login> is:pr is:open archived:false` |
| `$reviews` | `review-requested:<login> is:pr is:open archived:false` |
| `$mentions` | `mentions:<login> is:open archived:false` |

`<login>` must match `/^[A-Za-z0-9][A-Za-z0-9-]{0,38}$/` or throw pre-fetch. No `involves:`. If `login` is
absent, first POST `query{viewer{login}}` (+1 fetch, first run only). Re-sort `recentRepos` in JS (drop `orderBy` if rejected).

**REST fallback** (only if the GraphQL request itself fails, non-rate-limit):
```
GET /issues?filter=assigned&state=open&per_page=50
GET /search/issues?advanced_search=true&per_page=25&q=author:<login> is:pr is:open archived:false
GET /search/issues?advanced_search=true&per_page=25&q=review-requested:<login> is:pr is:open archived:false
GET /search/issues?advanced_search=true&per_page=25&q=mentions:<login> is:open archived:false
GET /user/repos?affiliation=owner,collaborator,organization_member&sort=pushed&direction=desc&per_page=30
```
(`q` URL-encoded; `GET /user` only if login absent.)

**Pagination:** none: one page (25) per bucket, keep `maxPerBucket`, `totals` from `issueCount`/`total_count`. **No retries.**

**Rate limits:** 403/429 with `x-ratelimit-remaining: 0` (or `retry-after`), or GraphQL `RATE_LIMITED` → throw
`GithubError` naming the reset; no fallback. 401 → throw.

**Graceful degradation (mandatory):** buckets fail independently. HTTP 200 with `errors[]` and
`data.<alias>: null`, or one failing REST call, marks only that bucket `partial`. A partial bucket
**reuses `previous`'s bucket and total** (last good data never wiped; `[]` if none). All parts failing → throw.

**Normalise:** drop empty union nodes, repos failing `/^[\w.-]+\/[\w.-]+$/`, `exclude`d repos. Rebuild
`url` as `https://github.com/<repo>/(issues|pull)/<n>`. **Dedupe** by `repo#number`, priority
`reviewRequests > assignedIssues > myOpenPrs > mentions`. Sort `updatedAt` desc, repo, number; cap at
`maxPerBucket`. `recentRepos.reason = "contributed"`.

## 2. `src/core/render/involvement.ts`

```ts
export const INVOLVEMENT_NOTE_PATH = "GitHub/involvement.md";
export function safeText(s: string, max?: number): string;   // default max 120
export function renderInvolvementNote(s: InvolvementSnapshot, maxPerBucket: number): string;
export function serialiseSnapshot(s: InvolvementSnapshot, maxBytes?: number): string;  // default 3000
export function renderInvolvementDigestSection(s: InvolvementSnapshot | null, maxPerBucket: number): string;
```

**Deterministic:** no wall clock/`fetchedAt`/"N days ago"; dates are `updatedAt.slice(0,10)`. Layout: frontmatter
(`type: github-involvement`, `login`, `scope`, `partial: [..]` only when non-empty, one numeric key
per bucket count, all via `frontmatter()`), `# GitHub involvement`, then sections *Review requested*,
*Assigned issues*, *My open PRs*, *Mentions*, *Recently contributed repos*. Headings show
`(shown of total)`. Item: `- [owner/repo #12 Title](url) — 2026-09-20`. Empty → `_none_`; partial →
`_unavailable this run (showing last good data)_` above its items.

`serialiseSnapshot`: JSON, titles cut to 80 chars, then drop trailing items (mentions first, then myOpenPrs, assignedIssues, reviewRequests) until ≤ `maxBytes`.
`renderInvolvementDigestSection`: `""` for `null`/all-empty; else `## GitHub involvement`, one count
line, up to `maxPerBucket` review-request and assigned lines, trailing `\n`.

**Security: titles are untrusted.** Every title goes through `safeText`: `clean()`, then strip control chars
`\u0000-\u001f\u007f` and bidi/zero-width marks, `<` `>` → `‹` `›`, drop a leading `#>!-*+=` run, truncate. Titles
appear only inside link text (never a raw line, heading or frontmatter) and are data: nothing here acts on their
content; P4 fences the kv snapshot before any model sees it. A repo name failing the regex is dropped, not sanitised.

## 3. `src/core/jobs/involvement.ts` — `export const pollInvolvement: JobSpec` (`poll:involvement`, `{ everyMinutes: 60 }`)

1. `enabled === false` → return `"disabled"` (0 fetches, 0 writes).
2. `login = kvGet(LOGIN_KV)`; `previous = parseSnapshot(kvGet(INVOLVEMENT_KV))`.
3. `fetchInvolvement({ token: await ctx.githubToken(), login, maxPerBucket, exclude: [ctx.env("VAULT_REPO")].filter(Boolean), previous, now, fetch: ctx.fetch })`.
   A throw propagates **before anything is written**: the last good note and kv survive.
4. `kvSet(LOGIN_KV)` if it was absent; `kvSet(INVOLVEMENT_KV, serialiseSnapshot(snap))`;
   `vault.writeFiles("poll:involvement <localDate>", [{ path: INVOLVEMENT_NOTE_PATH, content }])`.
5. Return `login=x review=n assigned=n prs=n mentions=n repos=n partial=n changed=0|1` (no titles/tokens).

**Budget** (free plan: 50 fetch + 50 D1 per invocation; cron starts no new job after 25 fetches):

| Step | Fetch | D1 |
|---|---|---|
| viewer login (first run only) | 0–1 | — |
| GraphQL | 1 | — |
| REST fallback (GraphQL failed) | 0 or 5 | — |
| kvGet ×2, kvSet (+1 first run) | — | 3–4 |
| vault commit (6 Git Data calls) | 6 | — |
| bookkeeping (`ensureJob`, `dueJobs`, `recordJobRun`, `setJobNextRun`) | — | 4 |
| **Steady state** | **7** | **7** |
| **Worst case** (login absent, GraphQL fails, REST, commit) | **1+1+5+6 = 13** | **8** |

13 < 25: another job can still start. `MAX_FETCHES = 8` bounds the source.

## 4. `src/core/index/**`

```ts
// tokens.ts
export function tokenize(s: string): string[];   // identical to retrieve.ts#tokenize (copy STOP; parity-tested)
export function buildEntry(path: string, content: string): { title: string; tokens: string; excerpt: string };
export function blobSha(content: string): Promise<string>;  // sha1("blob <bytes>\0"+content), crypto.subtle
// build.ts
export interface TreeEntry { path: string; sha: string }
export type TreeSource = (ctx: AgentContext) => Promise<TreeEntry[]>;
export const githubTree: TreeSource;   // Worker: ONE fetch
export const readTree: TreeSource;     // CLI/tests: listFiles + readFile + blobSha, no network
export interface IndexStats { indexed: number; removed: number; unchanged: number; pending: number }
export function buildIndex(ctx: AgentContext, tree?: TreeSource): Promise<IndexStats>;
// search.ts: null = index empty, caller runs the v1 path
export function retrieveFromIndex(ctx: AgentContext, question: string): Promise<Retrieved[] | null>;
// job.ts
export const indexVault: JobSpec;      // "index:vault", { everyMinutes: 30 }
```

- `buildEntry`: title = first `# ` heading else filename stem; `tokens` = deduped `tokenize(title+" "+body)` (frequency desc, then alpha), **cap 400**; `excerpt` = frontmatter-stripped, whitespace-collapsed body, first 600 chars.
- `githubTree`: `GET https://api.github.com/repos/<VAULT_REPO>/git/trees/<VAULT_BRANCH|main>?recursive=1`, token
  `GITHUB_TOKEN_VAULT ?? GITHUB_TOKEN` via `ctx.env`; keep `.md` blobs, no dot-segments; `truncated`/non-OK → **throw**
  (index untouched). Default source: `ctx.env("VAULT_REPO") ? githubTree : readTree`.
- `buildIndex`: tree sorted, first `index.maxNotes`; diff vs `listNoteIndex()` by sha; ≤ `index.batch` changed paths per run (`readFile`, null → skip, `buildEntry`, `upsertNote`); delete vanished paths in one chunk ≤ 50 (D1 binds ≤ 100). Steady state = 0 reads.
- `retrieveFromIndex`: `q = unique(tokenize(question))`, empty → `[]`; empty index → `null`. Score +3 per `q` token in
  `tokenize(path+" "+title)`, +1 per token in `tokens`; sort score desc, path date desc, path; keep `qa.maxNotes`;
  `getNoteExcerpts`; split `qa.maxChars` as v1. **0 vault calls, 0 fetches, 2 D1 queries.**
- `indexVault` returns `indexed=n removed=n unchanged=n pending=n`. **Budget:** 1 tree + ≤ 15 reads = **16 fetches**, no commit; D1 ≤ 1+15+1+4 = **21**.
