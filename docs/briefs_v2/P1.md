## 1. `src/core/reminders/rules.ts`

```ts
export const RULES_PATH = "Meta/rules.json", RULES_KV = "rules:json";
export const RULES_TTL_MS: number;                         // 3_600_000
export function parseRulesJson(text: string): ReminderRule[] | null;   // never throws
export function loadRules(ctx: AgentContext): Promise<ReminderRule[]>; // never throws
export function ruleFor(category: CategoryId, rules: ReminderRule[]): ReminderRule | undefined;
export function categorise(
  d: Pick<Deadline, "title" | "sourceRef" | "source"> & { category?: CategoryId },
  rules: ReminderRule[], extra?: string): CategoryId;
/** rule.offsets, or cfg.reminders.offsets for missing/"default"/empty-offsets rules. */
export function offsetsFor(category: CategoryId, rules: ReminderRule[], cfg: Config): string[];
```

### Detection order (first match wins; LLM never picks offsets or categories)

1. **Explicit**: `d.category` set, `!== "default"`, and a known rule id (manual-note
   frontmatter `category:`, chat `#tag`, P4's validated field). Unknown id → continue to 2.
2. **Source-bound**: first rule (config order) with non-empty `sources` including `d.source`
   (GitHub milestones → `github`). If it also has keywords, both must match.
3. **Keyword** (gmail, manual, chat, LLM-residue): haystack = lower-cased, whitespace-collapsed
   `title + " " + sourceRef + " " + extra` (`extra` = Gmail `from + " " + subject`). First
   rule in config order with any keyword as a substring (`includes`) wins.
4. **`"default"`**.

| id | offsets | match | needsTime |
|---|---|---|---|
| flight | `["24h"]` | flight, boarding, airline, pnr, indigo, vistara, air india, departure | yes |
| github | `["24h"]` | sources `["github"]` | no |
| assignment | `["2h"]` | assignment, submission, submit, viva, lab report, quiz, exam, practical | no |
| default | `reminders.offsets` | fallback | no |

Flight precedes assignment. Tests use this table as a fixture.

### `parseRulesJson` (any failure → `null`)
Accepts `[...]` or `{"rules":[...]}`, ≤ 20 KB. Entry: `id` matches
`/^[a-z][a-z0-9_-]{0,31}$/` (lower-cased), not `"default"`, unique; `offsets` strings that
pass `parseOffset` (try/catch) with span ≤ 30 d; `keywords` strings (trim, lower-case, drop
empties, ≤ 40); optional `sources` ⊆ github|gmail|manual|chat; optional boolean `needsTime`.
≤ 30 rules. `[]` is valid (everything default).

### `loadRules(ctx)`
1. `kvGet("rules:json")` → `{at, rules|null}`; fresh (< TTL vs `ctx.clock.now()`) → return
   `rules ?? config rules` (a bad file is cached as `null`, not re-read every sweep).
2. Else `vault.readFile("Meta/rules.json")`: absent/invalid → cache `null`, config rules,
   one `console.warn` (path only, never content). Valid → cache and return.
3. try/catch everything: any error → config rules. **Reminders never stop.**

## 2. `src/core/reminders/engine.ts`

```ts
export async function materialise(ctx, d: Deadline, rules?: ReminderRule[]): Promise<number>;
export async function materialiseAll(ctx): Promise<number>;   // loadRules once, pass down
export interface PlannedFire { kind: string; span: number; fireAt: Date }
export function planFires(due: Date, offsets: string[], tz: string, q: QuietHours): PlannedFire[]; // pure
```

`materialise`: non-open → unchanged. Else `rules ??= await loadRules(ctx)`;
`category = categorise(d, rules)` (handles old rows with no category and GitHub milestones,
which their job never stamps); `offsets = offsetsFor(...)`; `planFires`; keep the **existing**
late-discovery skip verbatim (`span > 0 && fire < now - span`). If any *unsent* existing row's
`kind` is not among planned kinds (category changed), `deleteUnsentReminders(d.id)` first
(`upsertReminder` preserves `sentAt`). Then `upsertReminder` each.

### Per-category invariant: no `fireAt` later than `due`
`fire = shiftOutOfQuietHours(due - span)`; if `fire > due` (timed 05:00 T-0 shifts to 08:00;
23:00 shifts to next 08:00) use the **unshifted** `due - span`: a quiet-hours ping beats one
after the event. Never drop an offset for this. 09:00 date-only deadlines are unaffected
(2h → 07:00 → 08:00 ≤ 09:00).

## 3. `src/core/reminders/categorise.ts` (pure chat helpers)

```ts
export function extractHashtag(text: string, rules: ReminderRule[]): { text: string; category: CategoryId | null };
export interface PendingWhen { title: string; date: string; category: CategoryId; explicit: boolean }
export type RemindProposal =
  | { ok: true; title: string; dueAt: string; category: CategoryId; timed: boolean;
      relative: boolean; date: string; time: string | null }
  | { ok: false; reason: "needs-time"; pending: PendingWhen; ask: string }
  | { ok: false; reason: "no-date" };
export function proposeReminder(text: string, rules: ReminderRule[], tz: string, now: Date, dueHourLocal: number): RemindProposal;
/** Bare-time reply to a needs-time proposal; null when no time is found. Uses ONLY .time. */
export function completePending(p: PendingWhen, reply: string, rules: ReminderRule[], tz: string, now: Date, dueHourLocal: number): Extract<RemindProposal, { ok: true }> | null;
```

`proposeReminder`: `extractHashtag` (explicit) → `parseLooseWhen` (null → `no-date`) → title =
text minus leading `remind me to | i have (a|an) | i've got (a|an)`, minus the when-phrase
(day words, weekday, date, time, dangling `on|at|by|for|due`), collapsed,
≤ 120 chars via `cleanTitle`, empty → category id → `categorise({title, sourceRef:"",
source:"chat", category: explicit}, rules)`. If `ruleFor(cat)?.needsTime && time === null` →
`needs-time`, `ask = "Flight on 4 Oct — what time? (e.g. '6pm')"`, nothing created. Else
`dueAt = dueAtFromLocalDateTime(date, time, tz, dueHourLocal)`, `timed = time !== null`.
Date-only stays 09:00 local via the canonical rule; `01/10/2026` stays refused.

## 4. Deadline extraction

Add optional trailing `rules?: ReminderRule[]` (default `ctx.config.reminders.rules`) to
`extractFromManualNotes`, `extractFromGmail`, `extractWithLlm`. `extractFromGmail` **stays
synchronous** (its caller is not yours). Every emitted Deadline carries `category`, `timed`.

- **Manual** (`rules ??= await loadRules(ctx)`): frontmatter `category:` (lower-cased, kept
  only if a known id) is explicit. `due: YYYY-MM-DD` (+ optional `time: HH:MM`) →
  `dueAtFromLocalDateTime`, `timed = time !== null`. `due: 2026-10-04T18:00` / `2026-10-04 18:00`
  (no zone) → **local time in `ctx.clock.tz`**, `timed:true` (v1 used host time).
  `Z`/`±hh:mm` → `Date.parse` as before, `timed:true`. `needsTime` does not apply (a note
  cannot be asked): date-only flight notes get 09:00, `timed:false`.
- **Gmail**: date-only from the subject as today, `timed:false`, never parse relative words
  ("tomorrow") from mail. Category = `categorise(d, rules, m.from + " " + m.subject)`.
- **LLM residue**: same derivation; the LLM is not asked for a category (`deadlinePrompt` is
  frozen); still `proposed`, confidence cap unchanged.
- GitHub milestones: no change; `materialise` categorises by source.

## Edge cases
Old rows without `category` still resolve; empty-`offsets` rule = default offsets; a flight
created 10 h out gets its past T-24h reminder once (v1 late-discovery rule); `needsTime`
never blocks Gmail/manual/GitHub ingestion.

## Security
Notes, emails, issue titles and chat text are **untrusted data**: only compared with
`includes` and parsed as dates. No `eval`, no regex from keywords, never in a path/URL/shell,
never log `Meta/rules.json` content, content never chooses offsets (only validated rule ids).

**`src/core/inbound/commands.ts`** (P0 left `remind` with `category:"default", timed:false`):
1. In the remind route (text `^remind me to\b`, or any text for which `proposeReminder` is not
   `no-date`, e.g. "I have a flight tomorrow 6pm"):
   ```ts
   const rules = await loadRules(ctx);                       // reminders/rules.ts
   const p = proposeReminder(text, rules, ctx.clock.tz, ctx.clock.now(), ctx.config.reminders.dueHourLocal);
   ```
   - `p.ok` → `{kind:"remind", title:p.title, dueAt:p.dueAt, category:p.category, timed:p.timed}`;
     the handler already passes them to `upsertDeadline` (`status:"proposed"`, `source:"chat"`).
   - `p.reason==="needs-time"` → `kvSet("pending:when:<channel>:<peer>", JSON.stringify({...p.pending, exp: nowMs+900_000}), nowIso)`,
     reply `p.ask`, create **no** deadline.
   - `p.reason==="no-date"` → existing routing (ask/help).
2. Before other routing: read `pending:when:<channel>:<peer>`; if unexpired,
   `completePending(pending, text, rules, tz, now, dueHourLocal)`; non-null → clear key
   (`kvSet(key,"",nowIso)`) and emit the same `remind` command (`timed:true`); null → route
   normally; expired → ignore.
3. Reply echoes the absolute date when `relative` ("Proposed: "flight" due Tue 22 Sep 18:00,
   from "tomorrow". Reply 'confirm 1'"); `timed:false` keeps today's date-only wording.
4. `confirm` keeps `materialise(ctx, {...d, status:"open"})` (rules resolve inside).
