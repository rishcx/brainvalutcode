## Database facts at ~09:40 UTC
* `deadlines`: exactly ONE row: id `chat:wamid...` (no ":0" suffix => created by the deterministic path in commands.ts, not by an LLM action), title **"Reminder"**, category default, timed=1, status open, due 09:35:00Z, source chat.
* `reminders`: one row kind "0", fire_at 09:35:00Z, **sent_at 09:36:27Z** (87 s late; the per-minute sweep job apparently missed the 09:35:2x tick and ran on the next one).
* The message sent for it is built by `formatReminderBatch` => a single item renders as `⏰ ${title}` => the owner received **"⏰ Reminder"**, with no subject and no indication of what it was for or when it was requested.
* `tasks`: ONE row, title **"buy milk , gym"** (created from the message `add task buy milk , gym`): several tasks in one message were stored as a single task. Local probe: `add task buy milk, gym and call mom` => one task "buy milk, gym and call mom".
* `kv last:list` = one deadline ref. (the last numbered list is per-bot, not per-channel)
* `processed` (inbound ids handled) shows a WhatsApp message handled at 09:35:47Z. There is NO chat_turn at that time, so it did not go through the LLM path, and the Worker log for the window contains NO exception/console output. The owner says the answer to "what are today's tasks" was "nothing". **We cannot tell what was sent** because deterministic replies are not recorded anywhere (only LLM-path turns are). This is itself a finding: there is no per-message trace (route taken, tool calls, reply sent, delivery result, latency).

## Local reproduction (FixedClock 09:35Z, one task "buy milk , gym", NO LLM configured)
```
tasks                       -> TASK-COMMAND   "Tasks for 2026-09-21:\n1. buy milk , gym"
show my tasks               -> TASK-COMMAND   same
what are todays tasks       -> chat/LLM       (deterministic fallback text when no model)
what are today's tasks      -> chat/LLM
Any task for today?         -> chat/LLM
tasks today                 -> chat/LLM
what do I have to do today  -> chat/LLM
add task buy milk, gym and call mom -> TASK-COMMAND "Added: buy milk, gym and call mom as item 1."  (one task, not three)
```
So most natural ways of asking for today's tasks are NOT deterministic; they depend on the LLM seeing the tasks in its context. Whether the live LLM path returned an empty/wrong answer for the owner's exact message is unproven.

## Other facts
* Reminders are sent to EVERY enabled channel (Telegram and WhatsApp), so the owner receives each reminder twice.
* Free-tier reality: OpenRouter free = 50 requests/day (exhausted). Groq free (verified key): qwen/qwen3.8-27b, openai/gpt-oss-120b, openai/gpt-oss-20b, 0.3-1.0 s, ~1000+ req/day. Worker limits: 50 subrequests and ~30 s after the webhook ack; per-call model budget is 12 s.
* Current design (already built): deterministic commands first (status, tasks, done n, confirm n, add task, rules), then `naturalReminder` (explicit "remind me ..." with relative-time parsing => active reminder; statements => proposal + confirm; explicit lead with no time => asks "when?" and remembers the title), then the LLM chat (`respond`) that returns JSON {reply, actions[]} with actions reminder/add_task/done_task/drop_task validated by a provenance check and executed by code; deterministic confirmation lines are appended by code.
* Known gap: `set a reminder` / `remind me` with NO title is not asked "what for?" (it creates "Reminder" or only asks "when").
