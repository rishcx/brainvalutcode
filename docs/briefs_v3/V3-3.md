## 1. `openaiCompat.ts`

```ts
export interface CompletionCall { /* existing */ responseFormat?: "json_object"; extraBody?: Record<string, unknown> }
export interface RateInfo { remainingReq?: number; remainingTok?: number; resetAt?: string; retryAfterMs?: number }
export async function openAiCompat(call: CompletionCall, now?: Date): Promise<{ text: string; model: string; usage?: { in: number; out: number }; rate: RateInfo }>;
export class LlmError { /* existing */ readonly rate?: RateInfo; readonly badParam?: boolean }
export function parseRate(h: Headers, now: Date): RateInfo;
```
- `extraBody` is merged into the body but can never override `model`, `messages`, `max_tokens`,
  `response_format`. `responseFormat` -> `response_format: { type: "json_object" }` unless `jsonSchema` is set.
- `parseRate`: `x-ratelimit-remaining-requests`, `x-ratelimit-remaining-tokens`, `x-ratelimit-reset-requests`
  (Groq durations like `2m59.56s`, `7.66s`, `1h2m` -> `resetAt = now + d`), `retry-after` (seconds, or an HTTP
  date) -> `retryAfterMs`. Missing/garbled headers -> fields absent, never a throw.
- `usage` from `json.usage.prompt_tokens/completion_tokens` when numbers.
- HTTP 400 while `extraBody` or `responseFormat` was sent -> `LlmError(..., badParam: true)`.
- Content: use `choices[0].message.content`; ignore any `reasoning` field; unchanged malformed handling.

## 2. `usage.ts`

```ts
export interface UsageView { day: string; rows: ProviderUsage[] }
export async function loadUsage(ctx: AgentContext): Promise<UsageView>;   // memoised per ctx (WeakMap), one D1 read
export function canUse(v: UsageView, entry: BrainEntry, model: string, cfg: Config, now: Date):
  { ok: true } | { ok: false; reason: "cooldown" | "exhausted" | "budget"; until: string | null };
export async function recordCall(ctx: AgentContext, entry: string, model: string,
  o: { ok: boolean; status?: number; usage?: { in: number; out: number }; rate?: RateInfo }): Promise<void>;
export async function quotaStatus(ctx: AgentContext): Promise<{ exhausted: boolean; resetAt: string | null }>;
export function extraBodyFor(entry: BrainEntry, model: string): Record<string, unknown> | undefined;
```
- `day` = UTC date (provider quotas reset on UTC days).
- `canUse`: cooldown_until > now -> cooldown; `remaining_req === 0` and (`reset_at` null or > now) -> exhausted;
  sum of today's `requests` over the entry's models >= `dailyBudget[entry.name]` -> budget (no key = unlimited).
- `recordCall`: `bumpUsage` with requests 1, tokens, `rateLimited` 1 on 429, `remainingReq/Tok/resetAt` from
  `rate`, `cooldownUntil = now + (retryAfterMs ?? 60 s)` on 429. Also updates the memoised view. Never throws.
- `quotaStatus`: exhausted when every non-local HTTP entry with a key configured fails `canUse` for every model;
  `resetAt` = the earliest `until` among them.
- `extraBodyFor`: if every key of `entry.extraBody` is `"*"` or one of `entry.models`, it is a per-model map
  (`map[model] ?? map["*"]`); otherwise it applies to every model. Honour a kv flag `brain:noextra:<entry>:<model>`.

## 3. `chain.ts`

- Budget: `purpose` in `plan|compose|summary` -> `chat.llmBudgetMs`; else `brain.budgetMs`.
  Per attempt: `req.timeoutMs ?? (chat purpose ? chat.perAttemptMs : max(2000, budget / 3))`, never above the budget left.
- Before each model: `canUse` false -> skip (no request). Send `responseFormat` only when `entry.jsonMode`;
  `extraBody` from `extraBodyFor`.
- After each attempt: `recordCall`. 429 -> next model. `badParam` -> retry the SAME model once without
  `extraBody`/`responseFormat` and set kv `brain:noextra:<entry>:<model>` = "1" (so the next call skips them).
- The result carries `usage` and `rate`. The JSON-parse check for `jsonSchema` is unchanged.
- Cache behaviour unchanged (chat passes `cacheTtlMs: 0`).

## 4. `agent/degraded.ts`

```ts
export async function degradedReply(ctx: AgentContext, msg: InboundMessage, reason: DegradedReason): Promise<string>;
```
Order: (1) `parseReminderRequest` explicit **with a real subject** (title not `Reminder|Timer|Alarm|default`) ->
`createReminder({..., id: "chat:<id>", origin: {channel, peer}})` if the V3-1 signature exists (else without origin)
-> `Reminder set: <title>, <when>. (offline mode)`; explicit without a subject -> `What should I remind you about?
My language model is unavailable, so please say it in one message, e.g. remind me in 10 minutes to call mom.`
(2) `parseTaskCommand` `addTask` -> one task (no splitting) + ` (offline mode)`; `tasks` -> `replyTasks`.
(3) Otherwise the honest line by cause (`quotaStatus`):
- quota: `My language model is out of free quota until about <HH:MM local> (<reset>). Reminders still fire. Meanwhile
  you can use: tasks, status, done 2, snooze 10m, remind me in 10 minutes to <thing>.`
  (`until about` omitted when `resetAt` is unknown: "for a while").
- unreachable / unparseable: `I couldn't reach my language model just now. Try again in a minute, or use: tasks,
  status, done 2, remind me in 10 minutes to <thing>.`
- no-brain: `No language model is configured. You can use: tasks, status, done 2, remind me in 10 minutes to <thing>.`
Never throws; plain text; <= 400 chars.

## Edge cases

429 without `retry-after`; `retry-after` as an HTTP date; `x-ratelimit-reset-requests: 1h2m3.5s`; a model at
`remaining_req 0` whose `reset_at` has passed (usable again); `dailyBudget` absent for a provider; D1 write failure
in `recordCall` (ignored); every model skipped -> deterministic floor without a single fetch; a hung fetch aborted
at `perAttemptMs`; `extraBody` trying to override `model` (ignored); UTC day rollover mid-conversation.

## Security

Keys only via `ctx.env`; error messages never include the URL or body; `extraBody` comes from config, not users.

## Tests (fakeFetch with scripted status/headers/bodies, FixedClock, counting fetch)

- Hung first model (never resolves) with `purpose "plan"` -> second model answers; elapsed < 4.5 s (use a small
  `perAttemptMs` in the test config, e.g. 200 ms).
- 429 + `retry-after: 30` -> cooldown row; the next `complete` skips that model with zero fetches to it; after 31 s
  it is used again.
- `remaining_req 0` + reset in 5 min -> skipped; daily budget 2 -> the third call skips the entry.
- 400 with `extraBody` -> same model retried without it, flag stored, next call sends no extra body.
- `response_format` sent only for `jsonMode` entries; `usage` recorded; `parseRate` duration formats.
- `degradedReply`: U5 (quota message with local reset time), U6 (`remind me in 10 minutes to x` sets it,
  "(offline mode)"), subject-less `set a reminder in 10 minutes` asks what, no row.
- Existing brain tests unmodified and green.
