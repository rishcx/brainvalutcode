# Cloud second brain: staging folder

Nothing in this folder is deployed or published. It is a staging area. **Confirm before running every step below**; each step touches the outside world (GitHub, Cloudflare). Anything marked `PLACEHOLDER-VERIFY` was written offline and must be checked by you; nothing has been built or run.

1. **Copy into the vault repo (confirm before running).** On a NEW branch of the vault repo, copy `site/quartz/` -> `quartz/`, `site/static/` -> `static/`, `site/.github/` -> `.github/`. Open a PR and review it. Do not merge to `main` until steps 2-5 pass (a push to `main` triggers a deploy).
2. **Verify Quartz and Node (confirm before running).** Check the newest Quartz v5 tag and set `QUARTZ_REF` in `.github/workflows/deploy-site.yml` (`v5.0.0` is a PLACEHOLDER-VERIFY). Node >= 22. Diff `quartz.config.ts` / `quartz.layout.ts` against the files in that tag and fix option or component names; also set `baseUrl` (PLACEHOLDER-VERIFY).
3. **Cloudflare Pages (confirm before running).** The workflow is guarded: it does NOTHING until you set the repo variable `ACCESS_CONFIRMED=true`, and you must only set that after step 5 passes. Create the Pages project; add repo variable `CF_PAGES_PROJECT`; create an API token limited to Pages:Edit; add repo secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.
4. **SRI hashes (confirm before running).** Run `site/scripts/verify.sh` (read-only). Replace each `sha384-FILL` in `static/mindmap.html` with the printed hash. Also confirm the three pinned versions and file paths exist on jsDelivr (PLACEHOLDER-VERIFY).
5. **5-minute Cloudflare Access verification (PLAN section I #4) (confirm before running).** Zero Trust > Access > Applications: add the Pages domain (production AND preview), policy "my email" with one-time PIN. Open the site in a private window: the Access login MUST appear before any content (`site/scripts/verify.sh <url>` also checks the redirect). **If it fails** (unavailable, not free, or not fronting the site): publish nothing, delete the Pages project, and use the fallback (the Worker serves the site behind the cookie login, a later phase) or keep using Obsidian/GitHub.
6. **Enable `/edit` (confirm before running).** `wrangler secret put ADMIN_TOKEN` (long random), set `EDIT_ENABLED=1`, deploy, log in at `/login`, edit a `Notes/` file and confirm the commit appears in the vault. Kill switch: `EDIT_ENABLED=0` (all `/edit` and `/login` routes then 404). Optionally put Cloudflare Access in front of `/edit*` and `/login` as well.
